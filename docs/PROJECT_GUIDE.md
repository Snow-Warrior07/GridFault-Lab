# GridFault Lab: complete first-version explanation

This guide explains the completed implementation step by step, with particular attention to **the models, the data, preprocessing/processing, and error management**. Read the [data card](DATA_CARD.md), [model card](MODEL_CARD.md) and [actual results](../results/SUMMARY.md) for precise assumptions and metrics.

## Step 1: Turn the project idea into a measurable problem

The original idea is that a user supplies whatever measurements are available for two buses and sees what information can be inferred. Version 0.1 makes that idea concrete for **one registered transmission circuit, bus 7 to bus 8**, in an adapted IEEE 9-bus network.

The system has three prediction tasks:

1. **Event recognition:** healthy operation, an internal fault on the monitored line, or an external fault elsewhere.
2. **Fault classification:** AG, BG, CG, AB, BC, CA, ABG, BCG, CAG or ABC for an internal fault.
3. **Fault distance:** distance from bus 7 along the assumed 120 km line, with a calibrated error band when the estimate is eligible.

The app checks measurement availability first. Six RMS voltage/current values at either end support a separately trained single-ended model. Twelve RMS values support a two-ended magnitude model. Complex phasors from both ends with a common reference support the electrical locator and richer classifiers. Partial measurements are not silently replaced with zeros. An incomplete or unsupported input produces an actionable explanation.

This is deliberately a defined benchmark rather than a claim to solve any two bus IDs. A future arbitrary-network application needs network registration, line/transformer topology, appropriate measurement profiles, and new held-out validation.

**Completed output:** a strict measurement schema, four trained input profiles, task selection, and an explicit inference router.

## Step 2: Build an electrical data generator

The input dataset is generated by solving a physical circuit, not by assigning arbitrary feature patterns to each fault label. The simulator constructs a three-phase nodal admittance matrix and solves:

```
Y V = I_Norton
```

Positive-sequence branch constants and nominal loads come from MATPOWER case9. An explicit bus-number mapping matches the review's diagram. The monitored branch is split into sections mZ and (1-m)Z around an inserted fault point. A fault is stamped as resistive phase/ground connections. Voltages and currents are then obtained from the circuit solution.

The solver returns phase-to-neutral RMS phasors and selected-line currents at both ends. Both current reference directions point into the line. Tests verify nodal current balance, negligible zero/negative sequence under a balanced healthy case, known fault positions, and distance-reference reversal.

There are important additional assumptions. Generators use grounded Norton equivalents; loads are constant admittances. Negative-sequence impedance equals positive, and branch zero-sequence impedance is assumed three times positive. The selected line is series-only, while other branches retain pi shunts. Its 120 km length is assumed. Actual monitored-line R and X vary independently by ±5%, while inference uses nominal parameters.

The circuit operates at the fundamental frequency. **It is not an EMT waveform simulator.** It does not contain traveling-wave arrivals, fault-inception dynamics, frequency-dependent line effects, realistic CT/CVT distortion, detailed transformer grounding or breaker dynamics. MATLAB became available after its licensing connection was allowed; it was used for an independent algebra check, not to generate an undocumented EMT dataset.

**Completed output:** `simulator.py`, explicit benchmark assumptions, electrical-invariant tests, and a separately executed MATLAB check on 50 clean cases. MATLAB's maximum normalized distance error was approximately 2.22e-16; that verifies algebraic agreement, not physical realism or field accuracy.

## Step 3: Generate and partition the dataset

There are **800 independent operating-condition groups**. Each group contains ten internal fault classes, one healthy scenario, and two external-fault scenarios, giving **10,400 physical scenarios**. Every scenario produces a clean and a noisy observation, giving **20,800 measurement records**.

The group conditions vary loading (0.65-1.35), source impedance strength (0.75-1.25), source angle, source voltage (0.97-1.05), phase load unbalance (up to 3%), and line R/X (±5%). Fault resistance is log-uniform from 0.5 to 80 ohm. Continuous location spans 5-95% of the line.

Noisy records add independent Gaussian real/imaginary phasor errors. Their levels are 20, 30, 40 or 50 dB, defined using the magnitude of each three-phase voltage/current vector. These are **complex-phasor SNR levels**, not raw waveform SNR.

The split is performed at the operating-group level before creating event cases and noise variants:

| Partition | Groups | Records | Used for |
|---|---:|---:|---|
| Training | 480 | 12,480 | Model parameters, feature scaling, clustering, support bounds |
| Validation | 120 | 3,120 | Temperature calibration of class scores |
| Calibration | 80 | 2,080 | Location-error bands after fixed model/gates |
| Test | 120 | 3,120 | Final evaluation |

All related observations stay together. The distance bands 20-25% and 70-75% are excluded from training, validation and calibration and explicitly sampled in testing. This is stronger than a random split of adjacent time samples or noisy copies.

The complete dataset is stored as a compressed CSV. Its manifest includes a SHA-256 digest, seed 20261126, record counts, assumptions, feature lists and provenance. Targets and simulator settings are stored for evaluation but are excluded from prediction features. Healthy/external monitored-line locations are null.

**Completed output:** the full dataset, manifest, split tests, supported input examples and deterministic generation code. No instructor data or measured utility events are claimed.

## Step 4: Preprocess measurements and construct features

All profiles use a consistent per-unit system. A 345 kV line-to-line, 100 MVA base gives a phase-voltage base of 345/sqrt(3) kV and current base of 100e6/(sqrt(3)*345e3) A. Real field voltages must first be converted with the correct sensor scaling and convention; the app intentionally rejects other declared bases.

Processing includes numeric/finiteness checks, metadata checks, channel checks, and consistency checks when both RMS and complex values are supplied. RMS magnitudes are calculated as abs(V) or abs(I), preserving their physical amplitude. Phase is used only when it is actually provided.

The four profiles are:

| Profile | Inputs | Features and location method |
|---|---|---|
| `rms_single` | Va,Vb,Vc,Ia,Ib,Ic at bus 7 | Six RMS magnitudes; learned distance |
| `rms_receiving` | Same six channels at bus 8 | Separately trained six-feature model; learned distance still referenced to bus 7 |
| `rms_double` | Both ends' V/I magnitudes | Twelve RMS features; learned distance |
| `phasor_double` | Synchronized complex V/I at both ends | 52 features; electrical distance |

The 52-feature set contains twelve magnitudes, 24 real/imaginary components, twelve sequence-component magnitudes, three differential-current magnitudes, and one normalized differential-current ratio. These are derived only from measured inputs. Differential current is highly informative in this simplified, uncharged monitored-line model; this partly explains the excellent synthetic classification scores.

Random Forest models do not require z-score scaling. ANFIS does: training-set means and standard deviations are stored and reused unchanged at validation, calibration, test and inference. Clustering also sees training data only. No principal-component transform, waveform denoising, DWT or LSTM is claimed in this release.

**Completed output:** shared feature definitions, strict input handling, four separate profiles and no missing-channel imputation. Python/browser feature processing is checked by full inference parity tests.

## Step 5: Train the model hierarchy

**Random Forest** is the default learned model family. A forest averages many decision trees so that one tree's sensitivity to the data is reduced. Every profile has an event classifier and an internal-fault type classifier. RMS profiles also have a distance regressor trained on m=d/L for internal faults only. Each forest has 40 trees, maximum depth 13, minimum leaf size 3, and a fixed seed. Classification uses balanced bootstrap class weights.

**ANFIS** is the paper-aligned reference for the six sending-end RMS inputs. It combines fuzzy rule activation with learned affine local functions. Its 100 Gaussian rules are initialized by k-means. Each rule evaluates membership in the standardized input space; normalized firing strengths combine its local prediction with those of other rules. Ridge least squares fits the consequent coefficients. Exact mean-square-error gradients update centers and log widths, followed by another least-squares fit. The release uses two premise-update epochs and a final consequent fit. Separate event, type and location models are trained. Classifiers use one-hot targets and are evaluated categorically.

This is an adapted Gaussian Sugeno hybrid learner, not the MATLAB Fuzzy Logic Toolbox's implementation and not a numerical reproduction of the paper's original dataset/results.

**The two-ended electrical locator** uses synchronized phase information and the nominal line matrix. With currents directed into the line:

```
Vf = Vs - m Z Is = Vr - (1-m) Z Ir
a = Z (Is + Ir)
b = Vs - Vr + Z Ir
m_hat = Re(a^H b) / (a^H a)
d_hat = 120 m_hat
```

It estimates one real distance from all three complex phase equations. It does not require the true fault class or true resistance under the registered series-line assumptions. Random Forest still identifies event/type for this profile. A separate single-ended reactance-loop baseline uses the true fault class for loop selection and is explicitly labelled an oracle-type comparator.

**Completed output:** trained JSON models and an explicit physics locator, with reusable Python inference and browser execution. There is no fake prediction service or manually assigned output table.

## Step 6: Measure errors and decide when to withhold an answer

Classification is assessed using macro-F1, per-class recall, confusion matrices and expected calibration error. Event metrics use all test events. Type metrics are labelled as using true internal-event membership; the pipeline also reports the fraction of all internal cases receiving a correct type after event recognition and abstention.

Location metrics use kilometres:

```
MAE  = mean(abs(predicted_distance - true_distance))
RMSE = sqrt(mean((predicted_distance - true_distance)^2))
```

The report includes 95th-percentile absolute error and mean error normalized by total line length. RMSE gives greater weight to large mistakes. MSE would have units km squared, whereas MAE/RMSE are in km. Location errors are reported alongside availability and false locations, so selective refusal is visible.

The measured release results are:

| Profile / method | MAE | RMSE | Location availability on internal faults | Empirical interval coverage |
|---|---:|---:|---:|---:|
| Bus 7 RMS / Forest | 9.14 km | 13.08 km | 99.96% | 92.25% |
| Bus 7 RMS / ANFIS | 7.81 km | 11.02 km | 99.67% | 91.01% |
| Bus 8 RMS / Forest | 14.34 km | 18.80 km | 96.50% | 88.77% |
| Both-end RMS / Forest | 3.66 km | 5.29 km | 100.00% | 89.54% |
| Both-end phasors / Forest + physics | 1.38 km | 2.77 km | 91.88% | 90.16% |

These error figures are conditional on accepted internal faults in 3,120 held-out synthetic records, including 2,400 internal records. The phasor locator returns a distance for 2,205 of those 2,400; the other 195 fail its physical checks. It assigns zero in-line distances to the 720 healthy/external records. RMS-only routes remain fallible: the sending, receiving and double-ended forest profiles produce 4, 13 and 3 false in-line locations respectively on those 720 records. This is a limitation to report, not something hidden by a high classification score.

Error management has several layers:

1. **Reject invalid input:** wrong circuit/base, non-finite or negative RMS, incomplete complex pairs, inconsistent RMS/phasors, or insufficient channels.
2. **Route missing data:** select a model trained for the measurements actually available. Unconfirmed synchronization disables the physical phasor locator and permits a supported RMS fallback.
3. **Screen training support:** reject features beyond training extrema extended by 15%. This is a heuristic, not a complete unknown-system detector.
4. **Calibrate scores:** fit a temperature on validation data. Event score below 0.65 withholds the event; type score below 0.55 withholds the class. A score of 100% on this benchmark is not a guarantee of field correctness.
5. **Check physical consistency:** reject the electrical locator if its denominator is negligible, its residual exceeds 0.35, or its distance lies outside [0,120]. Do not silently move an invalid point inside the line.
6. **Show uncertainty:** accepted internal calibration errors determine a symmetric 90%-target band. The radii are approximately ±24.26 km for sending-end RMS/Forest, ±18.09 km for sending-end ANFIS, ±29.05 km for receiving-end RMS/Forest, ±7.91 km for both-end RMS/Forest, and ±2.91 km for synchronized phasors. Bands are intersected with the line boundaries. Actual test coverage, not just target coverage, is shown.
7. **Report remaining mistakes:** include refusals, missed events, false locations, per-class errors and noise-specific results. The broad RMS bands correctly convey their coarser information content.

Correlated group variants and distribution shifts mean the bands should not be described as an unconditional distribution-free guarantee. An exact true SNR is also not inferred for an arbitrary uploaded record without a clean reference. Noise robustness and basic input quality checks are separate capabilities.

**Completed output:** full held-out metrics, uncertainty calibration, physical/domain/confidence gates, noise comparisons, standalone PNG/SVG figures and regression tests.

## Step 7: Make the model usable and host it

The static workbench accepts manual RMS/phase values, JSON, and a strict one-record CSV template. It exposes supported profiles and lets the user select detection, type, and location outputs. All predictions still pass through event and quality prerequisites. It shows measured phase voltages, a fault diagnosis, a distance band when eligible, and readable rejection explanations.

GitHub Pages serves static assets rather than a Python model server. To make the deployed app perform genuine inference, the fitted forest nodes, ANFIS parameters, calibration settings and physical matrices are exported as JSON. A JavaScript implementation executes the same models. A 120-fixture test compares full browser/Python predictions to within 1e-8, including all families/profiles. Browser tree comparisons reproduce scikit-learn's float32 feature comparisons.

Measurement files stay in the browser; there is no external prediction API. Python remains the reproducible simulator/training/evaluation implementation. GitHub Actions runs tests and publishes the browser app. A deployable interface does not extend the electrical model's validated scope.

**Completed output:** source, data, learned models, documentation, evaluation, automated tests and a GitHub Pages workbench under the requested Snow-Warrior07 account. The final chat message supplies verified repository and live URLs.

## What to demonstrate to the instructor

Open an AG example with synchronized phasors and inspect its diagnosis, physical position and interval. Expand "Show simulation reference" to compare the known simulated label/distance and absolute error. That reference is never passed to the predictor; editing a numeric measurement clears the reference. Switch to RMS-only inputs and observe that a different trained model and wider error band are used. Remove the receiving end and repeat. Load a healthy and an external case to see that an in-line location is not applicable. Break an input contract to show an actionable refusal. Open Evaluation to compare actual errors and availability, then use the data/model cards to discuss exactly what has and has not been validated.

The next substantial research step is independent Simulink/EMT or measured relay data, including sensor/transformer errors and causal fault windows. Further work can compare DWT/LSTM features, broaden line/topology coverage, identify supported physical parameters, and study simulated control actions. This release establishes a functioning, inspectable baseline for those experiments.
